# 雪嶺の黒騎士 五路 — Code 引き継ぎ資料

この資料と同じフォルダのファイル一式を Code に渡して、開発を続けてください。
最初に「この HANDOFF.md を読んで、今の `index.html` を動く状態のまま引き継いで」と伝えると始めやすいです。

---

## 1. どんなゲームか

- ボクセル（ブロック）で作った黒騎士が、スキーで夜の雪山を下る **3D の音ゲー**
- 曲に合わせて、前から迫る「氷の亡霊」を刀で斬り、氷柱や低い氷の壁をよける
- **5 本のレーン**（0＝左端、2＝中央、4＝右端）
- ミスしても最後まで続く。結果画面で「斬った数・一閃の数・ミス数」を出す
- 敵と障害物の配置は、手で一つずつ設計した **固定コース**
- ブラウザで開くだけで動く **1 つの HTML ファイル**（ビルド不要）

## 2. 操作とルール（決定済み。変えるときは必ず相談）

| キー | 動作 |
|---|---|
| A / D | 左 / 右のレーンへ 1 つ移動 |
| W | ジャンプ（低い氷の壁を越える） |
| ← / ↑ / → | 左どなり / 同じレーン / 右どなりの敵を斬る |
| R | おすすめルート表示の ON / OFF |

最初の画面で「速さ」を ふつう（172）／ゆっくり（140）から選べる。コースは拍で書かれているので、テンポを下げると間隔が広がる。
判定に成功すると「はやい／おそい」を表示し、斬った音（一閃は高い音）が鳴る。空振りは風切り音。

- **斬るキーは「今いるレーンから見た敵の方向」で決まる**。敵ごとに決まったキーは無い
  - 例：中央にいて中央から敵が来たら ↑。右にいるべき場面でも、中央にいれば ↑ で斬れる
- 刀が届くのは **自分のレーンと左右どなり** まで。2 レーン以上離れた敵には届かない
- 判定：敵の到着時刻から **±0.1 秒** 以内で成功。**±0.045 秒** 以内は「一閃」
- **自分のレーンの敵** を斬りそこねたときだけミス（被弾）。ほかのレーンの敵は、斬らなくても当たらない
- 氷柱：通過する瞬間に、そのレーンにいたらミス（激突）。判定は「その時刻にいたレーン」（`laneAt(T)`）で行う
- 低い氷の壁：W をタイミングよく押す（±0.1 秒）。押さなければミス（激突）
- 最後の 1 回：3 体（レーン 1〜3）が同時に来る。↑ で回転斬りし、3 体まとめて倒す

### タイミングの見せ方（決定済み）
- 画面下のタイミングバーは **使わない**（ユーザーの判断で削除済み）
- 敵の頭上には「おすすめルートどおりに滑ったときに押すキー」の矢印を出す（ルートの帯とセット）。判定そのものは、今いるレーンから見た方向で決まる（矢印と違うキーでも、位置に合っていれば斬れる）
- 敵の足元の輪が、近づくほど明るく小さくなり、判定中は **赤** になる
- 赤い線（ストライクライン）が拍に合わせて脈打つ
- 氷柱の足元にはオレンジの印、壁と氷柱の上には「W」「!」の印を出す

## 3. 曲

- 曲はブラウザ内で **Web Audio API で合成** している（音声ファイルなし）
- テンポ 172、E マイナー、ドラムンベース風、約 56 秒（40 小節＋決め）
- 構成：イントロ（0〜7 小節）→ ブレイクビーツの盛り上がり（8〜15）→ 1 回目のサビ（16〜31）→ より激しい 2 回目のサビ（32〜39）→ 40 小節目の頭で決め
- メロディとアルペジオの並びは、プレイごとに乱数で少し変わる。**コースは固定**
- 曲とノーツは同じ拍データから作るので同期している。時刻の基準は `AudioContext.currentTime`（`outputLatency` を補正）

## 5. コードの構成（`index.html` の中）

上から順に、次のまとまりになっている。

1. ボクセルの道具：`Vox`（ブロックの集まり）、`voxGeo`（見えている面だけのメッシュ化）
2. 黒騎士のモデル：部品ごと（腰・胴・頭・腕・前腕・大剣・太もも・すね・スキー板・マント 3 枚）に作って関節でつなぐ。`makeKnight()`
3. モーション：`pose()`。基本はスキー姿勢。`act()` で「右なぎ・左なぎ・振り下ろし・回転斬り・ジャンプ・よろけ」を重ねる。スキー板は常に雪面と平行になるよう補正している
4. 敵と障害物のモデル：氷の亡霊・氷柱・低い氷の壁・木
5. 演出：剣の軌跡（`Trail`）、砕けるブロック（`Burst`）、光の輪（`Arcs`）、発光（UnrealBloomPass）、ヒットストップ、画面の揺れ
6. 背景：雪面と崖（行ごとに使い回す InstancedMesh）、木、オーロラ、星、遠くの山、スピード線、雪
7. 音：`voice / bell / choir / kick / snare / reese` などの音源と、`playStep()`（16 分音符ごとに鳴らす）
8. コース：`COURSE` と `PATH`、`genChart()`（COURSE をノーツに変換）
9. おすすめルート表示：`PATH` から雪面に水色の帯を描く
10. ゲームの状態・判定：`slash / jump / move / laneAt / miss / hitEnemy`、デモ用の `autopilot`
11. メインループ：`frame()`

外部ライブラリ：three.js r128 と、その `examples/js` の後処理（EffectComposer・RenderPass・ShaderPass・UnrealBloomPass）を CDN（jsdelivr）から読み込んでいる。

## 6. コースの作り方（配置ルール）

コースを直すときや新しく作るときは、次のルールを守り、**必ず `course.py` で検証を通す**こと。

- データ形式：`(拍, コード)`。拍は曲の頭からの拍数（小節×4＋拍）
  - `E2`：レーン 2 に敵
  - `O034`：レーン 0・3・4 に氷柱
  - `J`：低い氷の壁（押す時刻。壁が騎士に届くのは 0.25 秒後）
  - 最後に `F`：3 体同時（回転斬り）
- 設計の考え方：先に「気持ちよく滑る線（ルート）」を決め、その線の左右 1 レーン以内に敵を置く。氷柱はその線を押し出す位置に置く
- **移動は 0.5 拍に 1 レーンまで** で全部の敵を斬れて、全部の氷柱をよけられること
- `course.py` はこの条件で、全部を満たすルートが 1 本以上あるかを自動で確かめる（見つからなければ `IMPOSSIBLE` と、つまずいた拍を出す）。見つかったルートが `path`（おすすめルート）で、デモ走行と水色の帯はこれを使う

コースの流れ（今の五路）：
- 2〜7 小節：中央中心。1 本の氷柱をよける練習
- 8〜15：階段（1 拍ごとに右へ 1 レーン、↑で斬り続ける）、挟み撃ち（← → を 8 分で交互に）、回廊（中央だけ空く）、横断
- 16〜31：右端から左端までの下り → 右への振り戻し、を繰り返す
- 32〜39：ジグザグの氷柱を縫うスラローム、8 連打、壁 → 回廊 → 最後の回転斬り

## 7. 分かっている課題

- キーボード操作と音のずれは、実機で細かく確かめていない（開発環境ではデモの自動走行と画面の見た目だけ確認）。まず実機で遊んで、ずれがあれば直す
- タイミング調整（音と判定のずれを自分で合わせる設定）がまだ無い
- スマホ・タッチ操作には未対応（PC のキーボード前提）
- 記録（ハイスコア）の保存がまだ無い
- 剣の振りは手作りのモーション。よりリアルにするなら Mixamo などのモーションデータを使う案がある（ボクセルの見た目は保つ）

1. **今の `index.html` をそのまま動かして、遊べることを確認する**（見た目・操作・判定・曲を変えない）

3. 設定画面に **タイミング調整**（±0.2 秒、0.01 秒刻み）を追加
4. `course.py` の検証を JavaScript に移して、ゲーム起動時にもコースを検証する
5. 結果画面にランク（例：一閃の割合とミス数で S〜C）と、ハイスコアの保存（localStorage）
6. 曲とコースを増やし、曲を選ぶ画面を作る。コースは必ずルールに沿って作り、検証を通す
